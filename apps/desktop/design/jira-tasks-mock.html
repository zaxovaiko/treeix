Jira tasks

Your Jira work items through Atlassian CLI (acli). Loaded only when enabled.

Jira JQL

Which items the tab lists

assignee = currentUser() AND statusCategory != Done

Setup states

Atlassian CLI not foundInstall it, then check again.
brew tap atlassian/homebrew-acli && brew install acli
Not signed in to JiraOpens the browser to authorize.
acli jira auth login --web

Data via CLI

  • List: acli jira workitem search --jql … --json
  • Detail: acli jira workitem view KEY --json
  • Status: acli jira workitem transition --key KEY --status …
  • Command list gets checked against the installed acli version before building.

Optional and lazy

  • Off by default; toggle in Settings like the other modules, the tab disappears when off.
  • Renderer: React.lazy(() => import('./JiraTasks')), a separate chunk fetched only when the tab opens.
  • Main: acli is never spawned while the module is off; acli shows up in Command line tools only when on.

Tie-ins

  • Open worktree: branch fix/KEY-slug, new worktree, agent session started with the item as context (not submitted).
  • Branch and PR titles containing the key link back to the item; PR list shows the key pill.
  • A reuses the PR tab layout; B suits sprint boards; C adds no new tab and keeps tasks next to code.
