Detection

  • Stack = chain where a PR base branch is another open PR head branch
  • GitHub native stacks (when repo has them) used first, branch chain as fallback, same for GitLab MR dependencies
  • Merged parents stay in stack, dimmed, until the whole stack lands

Review flow

  • Files changed defaults to this PR only (diff vs parent head, not trunk)
  • ⌥[ ⌥] move down/up the stack, keeps tab and scroll
  • Comments from other levels shown as a count on each crumb

Actions

  • Open stack in worktree: checks out top branch, all levels available in sidebar
  • Restack: rebase children after parent changes, via agent session or git rebase --update-refs
  • Merge bottom-up: merges ready prefix, retargets next PR base to trunk
